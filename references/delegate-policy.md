# Delegate Policy Reference

この文書は、`~/.agents/AGENTS.md`に記載されたdelegate方針の詳細である。実行時のMCP可用性やhookから注入される情報は、現在のhookと動的ツール一覧を正本とする。

## 委任経路と可用性

- Codex MCPは`mcp__codex__codex`が完全一致で存在する場合だけ開始可能と判定する。
- 継続対話が必要な場合だけ、`mcp__codex__codex_reply`の完全一致を別途確認する。
- 動的一覧を確認できない場合は`unknown`とし、MCP障害とは断定しない。
- 委任先からの再委任は禁止する。tmux paneや外部ラッパー経由の委任も行わない。
- MCP起動の最小確認は、新規セッション、設定変更後、または接続不安時に限る。

## 選択基準

| 作業 | 候補 | 条件 |
|---|---|---|
| Tier 1限定 | Ministral | 単一目的、入力範囲と出力形式が明示済み、読み取り中心、親が検証可能 |
| 並列読み取り | subagents | 同じモデル・reasoning effortで足り、独立実行できる |
| Tier 2以上・実装・コードレビュー | `gpt-5.6-luna` / `max`または親 | 入出力と検証を固定でき、親が差分を確認できる |
| 設計判断・複雑な原因追跡・最終判定 | 親 | 要件整理、優先順位、統合、品質判断を含む |

Ministralは、短いログ分類、明示入力からの短い項目抽出、固定形式の短いJSON変換、入力不足時のfail-close、`isometric-story-workflow`の画像一次解析に限り候補にする。コードレビュー、候補ファイル編集、保存後の再検証を含むツール連鎖、複数ファイルの原因追跡、設計判断、最終品質判定には使わない。

## 委任単位

- 大きな依頼は調査、変更、検証など、単独で完結・判定できる小タスクへ分割する。
- 変更委任の粒度は工程全体ではなく、不具合または変更点1件とする。
- 同じジオメトリ・同じ設定を触る不可分な組だけはまとめてよい。まとめる理由を委任文に明記する。
- 1件ごとに、実装、保存、保存後の再読込・再測定、確認を完了してから次へ進む。
- 継続対話が必要な場合は同じthreadで継続し、前の結果を親が確認するまで次のタスクを投げない。

## 委任文の必須項目

委任先へは毎回、次を明示する。

- Objective
- Allowed paths
- Prohibited operations
- Expected result
- Verification
- Completion criteria
- 親が要件整理・設計判断・統合判断を担い、委任先は指定済みの作業に限定すること
- 親の承認済みであり、`y/n`確認を求めず実行して結果を返すこと
- 範囲外、要件未確定、上位指示との競合時は実行せず報告して終了すること

## 権限と変更範囲

- 読み取りは`read-only`、書き込みは`workspace-write`、approval policyは`never`を既定とする。
- `cwd`は委任対象に限定する。許可パス外へ影響する作業は親が事前に確認する。
- 委任先は親が用意した候補ファイルと明示した出力・証跡だけを変更する。
- 正本、manifest、state、設計書、レビュー判定は委任先が更新しない。
- 入力素材・依存物の検索、選定、取得は親が事前に確定する。
- 依存関係追加、認証情報の取り扱い、外部サービス・ネットワーク操作、削除、DB操作、gitのcommit・push・branch・merge・PR作成は禁止する。

## 検証と統合

- 修正委任では、保存後に開き直して再測定する条件を必ず含める。
- 見た目・体感の問題を測定条件へ翻訳する場合、測定方法が対象自身や隣接対象と干渉しないかを親が先に確認する。
- 親は委任後に実際の差分を確認する。git管理外では、保護対象のmtime、参照整合フィールド、許可パス内だけへの出力を確認する。
- 空応答、タイムアウト、許可範囲外の変更、期待と異なる結果は失敗として扱い、自動再委任しない。
- 品質ゲートの合否、最終統合、commit、push、ユーザー報告は親が行う。
- 委任した場合の最終報告には、タスク、thread、委任先の結論、親が確認した差分を含める。
