# Delegate Policy Reference

この文書は、`~/.agents/AGENTS.md`に記載されたdelegate方針の詳細である。実行時のMCP可用性やhookから注入される情報は、現在のhookと動的ツール一覧を正本とする。

## 委任経路と可用性

- 委任可能な作業の標準モデルは`gpt-5.6-luna`、reasoning effortは`max`とする。
- Claude親はCodex MCP、Codex親はnative subagentを標準経路として使う。
- Codex MCPは`mcp__codex__codex`が完全一致で存在する場合だけ開始可能と判定する。
- 継続対話が必要な場合だけ、`mcp__codex__codex_reply`の完全一致を別途確認する。
- 動的一覧を確認できない場合は`unknown`とし、MCP障害とは断定しない。
- Codex親がnative subagentでLuna/maxを指定できない場合も`unknown`または`false`として扱い、別モデルへ黙って切り替えず親が担当する。
- 委任先からの再委任は禁止する。tmux paneや外部ラッパー経由の委任も行わない。
- MCP起動の最小確認は、新規セッション、設定変更後、または接続不安時に限る。

## 選択基準

複雑な原因追跡・依存の強い作業・複数成果物をまたぐ作業でも、親はまず独立した小単位へ分解する。分割可能な読み取り・実装・レビュー・再検証はLuna/maxへ委任し、親は分解、横断的な因果統合、設計判断、最終品質判定を担う。

| 作業 | 候補 | 条件 |
|---|---|---|
| 複雑な作業の分解・タスク整理 | 親 | 独立した小単位に整理し、分割可能な単位をLuna/maxへ委任する |
| 分割可能な読み取り・抽出・探索 | `gpt-5.6-luna` / `max` | 単一目的、入力範囲と出力形式が明示済み、親が検証可能 |
| 実装・コードレビュー・保存後の再検証 | `gpt-5.6-luna` / `max` | 入出力と検証を固定でき、親が差分を確認できる |
| 並列読み取り | `gpt-5.6-luna` / `max` | 独立実行でき、同じモデル・reasoning effortで足りる |
| 分解後の横断的な統合・設計判断・最終判定 | 親 | 要件整理、優先順位、複数結果の統合、品質判断を含む |

委任可能な作業でも、入力が曖昧、許可範囲を固定できない、Luna/maxの経路が`false`または`unknown`、または結果の検証条件を定義できない場合は親が担当する。別モデルへの暗黙のフォールバックは行わない。

## 委任単位

- 大きな依頼は調査、変更、検証など、単独で完結・判定できる小タスクへ分割する。
- 変更委任の粒度は工程全体ではなく、不具合または変更点1件とする。
- 同じジオメトリ・同じ設定を触る不可分な組だけはまとめてよい。まとめる理由を委任文に明記する。
- 依存関係のないタスクは並列に実行する。各タスク内では、実装、保存、保存後の再読込・再測定、指定検証までを完了させる。
- 前段の成果物を必要とする後続タスクだけは、親が前段の結果を確認してから実行する。継続対話が必要な場合は同じthreadで継続するが、独立したタスクの開始を待たせない。

## 委任文の必須項目

委任先へは毎回、次を明示する。

- Objective
- Fixed inputs（開始revision、対象ファイル、データ、使用コマンドなど）
- Allowed paths
- Prohibited operations
- Expected result、output format、保存先
- Verification
- Completion criteria
- Stop conditions
- 時間が延びやすい作業では、対象数、ファイル数、候補数、コマンド数、実行時間などの上限
- 親が要件整理・設計判断・統合判断を担い、委任先は指定済みの作業に限定すること
- 親の承認済みであり、`y/n`確認を求めず実行して結果を返すこと
- 範囲外、要件未確定、上位指示との競合時は実行せず報告して終了すること
- 結果は`DONE`、`FAILED`、`BLOCKED`のいずれかで返すこと。`DONE`は完了条件と検証をすべて満たした場合だけ許可し、`PARTIAL`、空応答、タイムアウト、許可範囲外の変更は成功として扱わないこと。

## 権限と変更範囲

- 読み取りは`read-only`、書き込みは`workspace-write`、approval policyは`never`を既定とする。
- `cwd`は委任対象に限定する。許可パス外へ影響する作業は親が事前に確認する。
- 委任先は親が用意した候補ファイルと明示した出力・証跡だけを変更する。
- 正本、manifest、state、設計書、レビュー判定は委任先が更新しない。
- 入力素材・依存物の検索、選定、取得は親が事前に確定する。
- 依存関係追加、認証情報の取り扱い、外部サービス・ネットワーク操作、削除、DB操作、gitのcommit・push・branch・merge・PR作成は禁止する。

## 検証と統合

- 修正委任では、保存後に開き直して再測定する条件を必ず含める。
- 見た目・体感の問題を測定条件へ翻訳する場合、測定方法が対象自身や隣接対象と干渉しないかを親が先に確認する。
- 親は委任後に実際の差分を確認する。git管理外では、保護対象のmtime、参照整合フィールド、許可パス内だけへの出力を確認する。
- 空応答、タイムアウト、許可範囲外の変更、期待と異なる結果は失敗として扱い、自動再委任しない。
- 品質ゲートの合否、最終統合、commit、push、ユーザー報告は親が行う。
- 委任した場合の最終報告には、タスク、thread、委任先の結論、親が確認した差分を含める。
