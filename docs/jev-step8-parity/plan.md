## 目的

`isometric-story-workflow` の Step 8A/8B/8C（現在は Opus の独立レビュー）を、Jev の事前判定で一部置き換えられるか検証する。主目的はトークン消費の削減。

## 前提

- Opus の判定を正解とはみなさない。Opus と Jev が食い違った項目は人間が判断し、その結果を正解として採点する。
- 合格事例だけでは評価できないため、過去に指摘を受けて修正した「修正前の画像」を必ず含める。
- 最重要の指標は見逃し率。Jev の判定が厳しすぎる側の誤り（問題ないものを不合格にする）は許容範囲を広く取る。
- Jev は実験的な画像入力機能（1.14、opt-in ヘッダー）を使う。Box（位置検出）は「見つからない」と答えられないため使わない。
- Jev の呼び出しには共通関数 `shared/jev/src/jev-client.mjs`（`askJev`）を使う。

## 手順

1. **データ収集**：過去の Step 8 の証跡から「画像・観点・判定項目・Opus の判定・その後の修正の有無」を 1 行ずつ並べた表（`dataset.jsonl`）を作る。
2. **問いの設計**：8A と 8C は項目をそのまま Yes/No の問いにする。8B は過去の指摘を分類し、分類ごとに定型の問いを作る。
3. **実行**：Jev 1.14 で判定と確率を記録する。必要なら Opus 5.5 も同じ問いで判定し直す。トークン量と費用を記録する。
4. **採点**：食い違った項目を人間が判断したうえで、下の合否基準で評価する。
5. **判断**：観点ごとに置き換えの可否を決める。置き換えを認めた観点も、本番で数クール Opus と並行して動かしてから切り替える。

## Step 2.5: 画像入力の確認テスト（2026-10-18 承認）

50 行を流す前に、Jev が画像を受け取り内容を見て答えているかを少数のリクエストで確かめる。
スクリプトは `smoke/`。API 呼び出しは親が行う（外部サービス操作のため委任しない）。

| 確認 | 方法 | 合格の目安 |
|---|---|---|
| 画像を見て答えるか | 明らかな問い（写っている物 / 写っていない物）を画像付きで送る | 正解側 ≥ 0.9、不正解側 ≤ 0.1 |
| 画像なしと区別できるか | 同じ問いを画像なしで送る | 画像付きとの差が 0.3 以上 |
| 日本語で動くか | 同じ問いを日本語と英語で送る | 結論（0.5 を境にした Yes/No）が一致 |
| サイズ・枚数の上限 | `questions.jsonl` で画像の合計サイズが最大の行を 1 回送る | エラーにならない |
| 費用 | `usage` のトークン数を記録 | 50 行 × 2 問の総量を見積もる |
| 結果のぶれ | 同じリクエストを 3 回送る | 確率の最大差 ≤ 0.1 |

#### 判断

- **画像は届いており、内容を見て答えている。** 画像なしでは 0.05〜0.06 に落ち、画像ありでは 0.86〜0.95。日本語でも英語でも結論は同じで、ぶれも小さい。
- **明らかな問いでも 0.9 / 0.1 に届かないことがある。** トイクレイ調のレンダーでは確信度がやや下がる。Step 3 では「0.5 を境に判定し、0.2〜0.8 は不確実として Opus に回す」扱いが妥当。
- **サイズ不合格の原因は画像の寸法。** 完成 state 静止画は 1080×1920 で、Jev の上限（各辺 1568px 以下）を超える。クローズアップ（1080×1080 など）は問題ない。
  Step 3 では送信前に長辺を 1568px 以下へ縮小する（例：882×1568）。リクエスト全体の上限（32MiB）には余裕がある。
- **トークンの見積もり（Step 3）：** 1 行 1 リクエスト（問い 2 つ）、画像 1〜4 枚で、50 行合計は約 15〜30 万入力トークンの見込み。料金は未確認。

## Step 3 の準備（2026-10-18）

`lib/` に 2 つの部品を追加した（Codex に approved-write で委任し、親が差分とテストを確認）。Step 3 の実行スクリプトへの組み込みはまだ。

- `lib/prepare-image.mjs`：長辺が 1568px を超える画像を縦横比を保って縮小し、キャッシュ用のフォルダに保存する（元画像には書き込まない）。
  縮小には macOS の `sips` を使う。実画像で確認：1080×1920 → 882×1568。

  `toVerdict()` は問いの向き（`polarity`）を加味して `pass` / `defect` / `uncertain` / `invalid` を返す。`uncertain` は Opus に回す。
- テスト：15/15 合格（親が再実行して確認）。
