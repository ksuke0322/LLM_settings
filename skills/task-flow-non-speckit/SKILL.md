# Task Flow

`specs/flow/` 内のタスク lifecycle と worktree 運用に適用する。通常の開発タスク全般には広げない。安全境界、開始指示、承認の正本は `AGENTS.md` とする。Git / PR / merge / cleanup の具体手順は `skills/git/SKILL.md`、repo-wide の 1 task = 1 PR は `skills/task_common/SKILL.md` に従う。

## コア方針

- 原則は単一目的・単一成果物・限定的な影響範囲で分割する。複数目的や複数領域にまたがる場合は分割を検討する。
- 1タスクにつき1PRとする。タスクごとに専用 worktree で作業し、対象外の差分を混ぜない。
- **方針の了承は作業開始指示ではない。** `未着手 → 進行中` は明示された開始指示がある場合だけ許可する。
- ユーザーの「一旦停止」や作業停止指示を受けたら、保存と状態記録を行って止まる。明示的な再開指示が届くまで進行しない。
- `specs/flow` のタスク一覧では `未着手`、`進行中`、`検証中`、`承認待ち`、`blocked`、`失敗`、`確認不能`、`完了` をそのまま記録する。古い `done` は `完了` と同じ成果受入れ記録として読み替える。

## 状態定義

タスク状態は作業と成果受入れを表す。各行の入力、承認条件、証跡、次担当も状態記録に残す。

| 状態 | 開始・終了条件 | 入力 | 承認条件 | 証跡 | 次担当 |
|---|---|---|---|---|---|
| 未着手 | タスク範囲と期待値を定義済み。明示開始指示を受けると進行中へ移る | 目的、対象、期待値、作業計画 | 方針の了承だけでは開始しない。開始指示を要する | タスク記録、開始指示の記録 | 指名された作業担当 |
| 進行中 | 明示開始指示後に作業し、期待値を満たしたら検証中へ移る。停止指示で作業を止める | 承認済み範囲、作業対象、必要な入力 | 範囲外の変更や未承認操作を行わない | 変更記録、実行コマンド、停止理由 | 作業担当。停止中は再開指示者 |
| 検証中 | 期待値に対する検証を開始し、結果を得たら承認待ち、完了、失敗、確認不能のいずれかへ移る | 期待値、検証手順、必要な証跡 | 成果受入れ事前承認がなければユーザー承認を待つ | 実行コマンドと結果、受入れ証跡 | 検証担当または承認者 |
| 承認待ち | 検証済み成果または必須の業務書込に対する判断・承認を待つ。業務書込の承認後は実行・検証へ戻り、成果受入れ承認だけが残り全条件を満たせば完了へ移る | 検証済み成果、承認依頼、未実施の業務書込 | 同じ範囲の成果受入れ事前承認がない限り、明示承認を得る | 承認依頼、承認記録、業務書込結果 | 承認者または業務書込担当 |
| blocked | 必要な入力、判断、権限、外部依存を待つため進められない。依存解消後、保存状態を確認して再開する | 不足入力、依存先、再開条件 | 依存が解消するまで完了にしない | 保存成果、停止理由、依存先、再開条件 | 入力・依存の担当者 |
| 失敗 | 通常の実行または受入れ検証が失敗した。修正後に進行中または検証中へ戻す | 失敗した処理、期待値、再現入力 | 失敗した状態のまま完了にしない | エラー、コマンドと結果、保存成果、停止理由 | 修正担当 |
| 確認不能 | 証跡の欠落・読取不能などで結果を確定できない。証跡を回復した後に再検証する | 不足・不明な証跡、確認対象 | 結果を推測せず、確認不能の間は完了にしない | 不足内容、確認を試した記録、保存成果 | 証跡の所有者または検証担当 |
| 完了 | 期待値と受入れ条件を満たし、必須の業務書込も実施した状態。タスクの成果受入れを記録する | 受入れ条件、実施済み成果、業務書込結果 | 明示承認、または同じ範囲の成果受入れ事前承認とその証跡 | 受入れ証跡、承認または事前承認の記録 | Git / PR / cleanup の次担当 |

TDD予定Red確認は仕様を表すための検証手順であり、タスク状態の `失敗` や受入れ検証失敗とは区別する。受入れ検証が失敗した場合は `失敗` とし、未達を完了に読み替えない。

## 状態遷移

各遷移に開始・終了条件、入力、承認条件、証跡、次担当を記録する。空欄や未設定の担当・証跡を残さない。

| 遷移 | 開始・終了条件 | 入力 | 承認条件 | 証跡 | 次担当 |
|---|---|---|---|---|---|
| 未着手 → 進行中 | 明示開始指示を受けた時点で開始。作業担当が引き継いで作業を始めたら終了 | タスク範囲、期待値、開始指示 | 方針の了承は開始として扱わない。明示開始指示が必要 | 開始指示、範囲、担当者 | 作業担当 |
| 進行中 → 検証中 | 実装と対象作業を終え、期待値の検証を開始した時点 | 変更内容、期待値、検証手順 | 検証開始の追加承認は不要。範囲外作業は不可 | 差分記録、実行コマンド、検証対象 | 検証担当 |
| 進行中/検証中 → 承認待ち | 成果受入れまたは必須業務書込の承認・判断が必要になった時点 | 現在の成果、未実施の書込、判断事項 | 必要な明示承認が得られるまで実施・完了しない | 承認依頼、未実施事項、保存成果 | 承認者または業務書込担当 |
| 進行中/検証中 → blocked | 入力・権限・実行依存がなく、作業継続できない時点 | 不足入力、依存、再開条件 | 依存解消まで完了にしない | 保存成果、停止理由、依存先 | 依存の担当者 |
| 進行中/検証中 → 失敗 | 通常実行または受入れ検証で期待値を満たさない結果が出た時点 | 期待値、実行結果、再現条件 | 失敗を完了にしない | 失敗結果、コマンド、保存成果、停止理由 | 修正担当 |
| 進行中/検証中 → 確認不能 | 必要な証跡を読めず、結果を確認できないと判明した時点 | 確認対象、不足証跡 | 推測による完了は禁止 | 確認不能の理由、確認記録、保存成果 | 証跡の所有者 |
| 検証中 → 承認待ち | 期待値を検証し、成果受入れを依頼した時点 | 受入れ結果、期待値、残作業 | 同範囲の事前承認がなければ明示承認を待つ | 検証結果、承認依頼、証跡 | ユーザーまたは承認者 |
| 検証中 → 完了 | 同じ範囲の成果受入れ事前承認が記録済みで、期待値と必須業務書込を証跡で確認した時点 | 事前承認、検証結果、業務書込結果 | 事前承認の範囲が一致すれば再承認は不要。merge承認は成果受入れ承認に流用しない | 事前承認、受入れ結果、業務書込の証跡 | Git / PR / cleanup の次担当 |
| 承認待ち → 進行中/検証中 | 必須業務書込の実行承認を得た後、承認済み範囲で書込を実行し、結果の検証へ戻る | 承認記録、業務書込の内容、検証手順 | 書込の明示承認を確認する。既承認範囲内の実行に再承認は不要 | 承認、書込コマンドと結果、再検証結果 | 業務書込担当、次に検証担当 |
| 承認待ち → 完了 | 明示承認を得て、必須業務書込と受入れ条件を満たした時点 | 承認記録、受入れ結果、書込結果 | 同じ範囲の事前承認が記録済みなら再承認不要。未実施の業務書込があれば完了不可 | 承認または事前承認、検証、書込結果 | Git / PR / cleanup の次担当 |
| blocked/失敗/確認不能 → 進行中/検証中 | 保存成果・停止理由・再開条件・次担当を確認し、依存解消または修正・証跡回復後に再開 | 保存成果、停止理由、再開条件、復旧した入力 | 一旦停止後はユーザーの明示再開指示を得る。未解決状態から直接完了は禁止 | 引継ぎ確認、再開指示、復旧・修正証跡 | 記録済みの作業担当 |

`blocked`、`失敗`、`確認不能` が未解決の間は `完了` へ直接遷移できない。先に状態、保存成果、停止理由、再開条件、次担当を確認する。ユーザーが「一旦停止」を指示した場合だけ、明示的な再開指示が届くまで進行しない。それ以外は依存解消、修正、証跡回復後に既承認範囲内で `進行中` または `検証中` へ戻り、既承認の作業を再承認待ちにしない。停止理由が残る場合は停止状態を維持する。

必須の外部業務書込が未実施の場合、ユーザー判断・承認を待つなら `承認待ち`、入力・権限・実行依存を待つなら `blocked` とする。書込実績と証跡が揃うまでタスクを完了にしない。

## タスク受入れと Git lifecycle の分離

タスクファイルの `done` は、期待値の成果受入れを記録した旧表記である。タスクの `完了`（旧記録の `done`）は成果受入れだけを表し、lifecycleの最終完了を示さない。PRが未マージでも「タスク完了 / PR未マージ / 最終lifecycle未完了」と記録できる。タスク状態、Git反映、PR、cleanup、最終lifecycleを個別に更新する。

| 記録対象 | 状態・記録する値 |
|---|---|
| タスク状態 | 未着手 / 進行中 / 検証中 / 承認待ち / blocked / 失敗 / 確認不能 / 完了。旧 `done` は完了として記録 |
| Git反映状態 | 未着手 / commit済 / push済 / 未確認。commit SHA、push先、各操作の承認範囲と結果を記録 |
| PR状態 | 未作成 / 作成済・レビュー中 / 承認待ち / merge済 / merge未確認。PR URL、PR承認、merge承認、merge結果を個別に記録 |
| cleanup状態 | 未着手 / 保全確認中 / clean確認済 / worktree削除済 / 停止・保持。保全、clean、branch保持、削除結果を記録 |
| 最終lifecycle状態 | 未完了 / 完了。必須条件をすべて確認した証跡がある場合だけ完了 |

commit、push、PR作成、PR承認、mergeの承認範囲と実行証跡はそれぞれ分けて記録する。すでに明示承認された範囲の操作を再度承認依頼しない。未承認の操作はその操作の承認待ちとして止める。PRやmergeの承認を成果受入れ承認に流用しない。

最終lifecycleの完了には、タスク成果受入れ、必要なGit記録、main/masterへの反映確認、作業内容の保全、worktreeのclean確認、branchを保持した通常worktree削除が必要となる。リモートがありPRが存在する場合は、同一PRのmain/masterへのmerge確認を要する。リモートがない場合やPRが存在しない場合もmain/masterへの反映とcleanup完了は必要だが、同一PRのmergeを欠く削除は追加承認不要の例外に該当しない。個別承認と証跡を得るまでworktreeを保全して削除を停止し、最終lifecycleを未完了と記録する。承認証跡を確認した後に通常削除できる。具体的な承認・merge・cleanup手順は `skills/git/SKILL.md` に従う。

通常のworktree削除を追加承認なしで実施する条件は、同一PRのmain/masterへのmerge確認、作業内容の保全、worktreeのclean確認、branch保持である。条件が揃ったら必ず実施する。PR未マージ・merge未確認、dirty、未コミット差分あり、状態不明なら保全して削除を停止する。リモートがない場合、またはPRが存在しない場合はこの通常削除例外を使えない。main/masterへの反映確認後も、個別承認を得るまで保全し、cleanup状態を承認待ち・保持、最終lifecycleを未完了と記録する。承認証跡を確認してから通常削除する。`--force` による削除は個別承認を得る。

## 運用と記録

- `specs/flow` にタスクを作成し、目的・対象・期待値・作業範囲・受入れ条件を記録する。タスク分割は単一目的・単一成果物・限定的な影響範囲を基準にする。
- 着手前に main/master の状態と対象範囲を確認し、タスク専用の作業 worktree で作業する。命名は `skills/branch-worktree-naming/SKILL.md`、worktree開始条件は `AGENTS.md` に従う。
- 検証後はユーザーに結果を報告する。必須報告項目は、タスク状態 / Git・PR・cleanup・最終lifecycle状態、変更、実行コマンド、検証結果、残リスク、未実施事項、次担当。
- `完了` は成果受入れ記録であり、最終lifecycle完了を意味しない。PR未マージやcleanup未完了などの状態を独立して残す。

## タスクファイルテンプレート

```md
# <タスク名>

## 目的

<このタスクで達成すること>

## 受入れ条件

- <検証可能な期待値>
- 必須の外部業務書込: <なし / 内容と担当>

## 対象と作業

- 対象: <ファイル・領域>
- 作業: <実施内容>
- 次担当: <担当者または役割>

## 状態記録

- タスク状態: 未着手
- Git反映状態: 未着手
- PR状態: 未作成
- cleanup状態: 未着手
- 最終lifecycle状態: 未完了
- 成果受入れ承認: <未依頼 / 依頼中 / 承認済み / 同範囲の事前承認と証跡>
- Git操作・PR・mergeの承認範囲と証跡: <個別に記録>
- 受入れ証跡: <結果または保存先>
- 保存した成果: <変更・成果の所在>
- 停止理由: <なし / 理由>
- 再開条件: <なし / 条件>
- 次担当: <担当者または役割>

## 実行・検証記録

- 実行コマンド: <実行内容>
- 検証結果: <結果>
- 残リスク・未実施事項: <内容>

## Git / PR / cleanup 記録

- commit: <SHAまたは未実施>
- push: <先・結果または未実施>
- PR: <URL・状態または未作成>
- main/master merge: <結果または未確認>
- 作業内容の保全: <証跡>
- worktree clean: <確認結果>
- branch保持 / worktree削除: <結果または停止理由>
```

## 記録例

- **実装済み・承認待ち**: タスク状態を `承認待ち`、検証証跡と承認依頼を記録する。ユーザーが成果を受け入れた後に `完了` とする。同一範囲の受入れ事前承認があればその証跡で足り、再承認を求めない。
- **受入テスト失敗**: タスク状態を `失敗` とし、期待値、実行コマンド、失敗結果、保存成果、修正担当を記録する。修正後は `進行中` または `検証中` に戻す。
- **外部必須書込待ち**: 承認待ちか入力・実行依存による `blocked` を記録し、書込内容、未実施理由、担当、再開条件を残す。書込結果の証跡がない間は `完了` にしない。

未解決状態から作業を再開する場合、保存した成果、停止理由、再開条件、証跡、次担当を読み合わせて記録する。ユーザーが一旦停止を指示したタスクは、明示的な再開指示も記録してから再開する。
