# ブルアカの日課

ユーザーが開いたiPhoneミラーリングのゲーム画面を操作する。相談・調査・スキル編集だけの依頼ではゲームを実行しない。実行時は [references/account.md](references/account.md) の周回設定と検証状況、および [references/state.md](references/state.md) の再開・日替わりルールを読む。

## 実行範囲

- スケジュール2回、カフェの絆ポイント1回、サークルロビー1回入場。
- 任務Hard3回。指名手配・学園交流会は当日の選択対象で保有チケットを全消費する。
- 戦術対抗戦1回参加。保存済み攻撃編成を使い、勝つまで連戦しない。
- 既に達成した項目はスキップし、途中までなら残り回数だけ行う。ただし指名手配・学園交流会はミッション達成済みでも残チケットを掃討で使い切る。
- 実行前に当日限定の除外・追加指示を整理する。「今日は指名手配を外す」などの個別除外は、全チケット消費などの一般ルールより優先する。除外は当日の実行状態に保存し、再開時も維持する。翌日以降の恒久的な除外にはしない。
- 実行を依頼されたら、対象項目の完了または具体的な阻害理由の確認まで継続する。進捗報告や一部完了だけでターンを終了しない。
- デイリー報酬の受け取りとAP回復ミッションは対象外。
- 青輝石消費、AP・チケット・挑戦回数購入、ショップ交換、育成、募集、編成変更、サークル加入・脱退、未攻略ステージへの挑戦は含めない。
- スキルの存在は常時操作や定期実行の許可ではない。実行依頼の範囲で進める。

## 画面操作

UI操作は利用可能なcomputer-useツールを使う。iPhoneミラーリングを選び、初回にツールの操作仕様を読む。画面は画像で判断し、ゲーム内部APIや座標の固定値に依存しない。

- 操作後に最新画面を確認して次の操作を決める。読み込み・演出中に次のボタンを推測して押さない。
- リサイズ・接続復帰後は画面と座標を取り直す。エラーになったクリックを成功扱いにしない。
- 一覧は右のスクロールバーを少しずつ動かし、前の末尾と次の先頭を重ねて確認する。項目や行を飛ばさない。バーがなければ重なりを保った小幅スクロールにする。
- 個々のミッションの分子/分母と達成・受取済み表示を確認する。ホームの「8/8」だけで全項目完了と判定しない。
- ユーザーがミッション一覧の確認を省略するよう指定した場合は、保存済み手順と今回の実行記録に沿って進める。各操作に必要な資源・対象・結果は画面で確認し、同日再開時に完了済み操作を重複実行しない。確認できない項目をホームの件数だけで完了扱いにしない。
- 戦闘画面に入ったらAUTO ON・3倍速（黄色の三連矢印）を確認する。別モードでは設定が異なる場合があるため引き継ぎを推測しない。戦術対抗戦のAUTOは固定なので解除操作を試さない。

## 手順

1. 接続、対象アカウント、ゲーム内の日付、当日の除外・追加指示、APと対象のチケット数を確認する。ミッション一覧は確認省略の指定がなければ確認する。状態ファイルがなくても、今日未実行とは推測しない。
2. 未達成項目と必要回数を決める。周回は状態ルールに従い、当日の対象を確定して記録する。
3. 以下の操作を実行し、各結果を確認する。APやチケットが足りない項目だけ保留して、独立して実行できる項目を進める。
4. 操作結果と資源の実行前後を照合する。ミッション一覧の確認省略指定がなければ進捗も照合する。報酬は受け取らない。
5. 実行内容・消費・確認結果・保留理由を報告する。未検証手順は、観測できた範囲だけ検証済みへ更新する。

### スケジュール・カフェ・サークル

- スケジュール：利用可能な場所を選び、実行前に残チケットを確認する。2回達成するための残り回数だけ進行する。特定の生徒・素材の優先指定がなければ利用可能な場所を選ぶ。
- カフェ：絆を獲得できる生徒を1人タップし、獲得演出またはミッション更新を確認する。カフェ収入のAP・クレジットも受け取り、受取結果を確認する。贈り物は行わない。カフェ収入は対象外のAP回復ミッション報酬とは区別する。
- サークル：加入済みサークルの実際のロビーに入る。未加入なら保留する。

#### カフェの家具を誤操作しないための注意

- 日課で行うカフェ操作は、生徒の絆ポイント獲得と収入のAP・クレジット受取に限定する。家具の編集・配置・移動・収納には入らず、「すべて収納」は押さない。過去に日課中の誤操作で家具を全収納したため、この境界を厳守する。
- 入場後は現在の画面を確認し、生徒・収入受取のボタンを見分けてから操作する。編集画面や贈り物画面が開いていたら、変更・贈与を確定せず閉じ、通常のカフェ画面へ戻す。以前の座標だけで連続操作しない。
- 家具を誤って変更した場合は、それ以上の家具操作を止め、実際に行った操作と確認できた影響を報告する。日課の許可を家具の再配置・復旧の許可とみなさず、復旧範囲を確認してから進める。
- 「今回だけカフェを除外」は今回の実行にだけ適用する。次回の日課では、別途除外指示がなければ絆ポイント獲得と収入受取を通常どおり実行する。

### Hard・指名手配・学園交流会

- 除外対象には入場・出撃・掃討しない。当日のエリア・学園は日替わり割当を使う。
- 指名手配・学園交流会は、そのエリア・学園内の一覧を末尾まで確認し、★3済みで掃討可能な最高難度を選ぶ。Aや過去に周回したステージへ固定しない。例：トリニティBが★3、Cが未達成ならBを選ぶ。
- 対象名・★3・掃討解放・残り回数を確認する。クリア済みでも★3でなければ掃討可能とは扱わない。
- Hardは3回達成までの必要回数だけ設定する。指名手配・学園交流会は残チケット全部を選択ステージで使う（6枚なら6回）。MAX使用後も回数・AP・チケット・挑戦回数の差分を読み、意図した全消費と一致することを確定前に確認する。資源不足なら購入せず実行可能分を進め、残数と理由を報告する。
- 同一ステージの残回数だけで足りなければ、その項目を保留して報告する。別の対象へ黙って切り替えない。
- 掃討結果と消費、ミッション進捗を確認してから成功を記録する。
- 指名手配・学園交流会は初回のスキル実行時にこの手順で実地検証する。事前調査済みを掃討成功済みと取り違えない。

### 戦術対抗戦

チケット・待機時間・保存済み編成を確認する。画面上で比較できる候補から低レベルの相手を優先し、同条件なら最上段を選ぶ。対戦相手→攻撃編成→出撃→結果→ロビーの順に確認する。戦闘は自動進行を待つ。結果を閉じた後の残チケットと参加ミッションを確認する。ユーザーが既に参加済みなら通常の日課では追加出撃しない。

待機時間中は他の未達成項目を先に進め、必要なら残時間を待つ。購入による短縮はしない。

## 中断

通信エラーや接続切断で消費・結果が不明なら、再接続してミッション・資源・結果表示を照合する。解消できなければ該当操作を再実行せず「結果不明」として停止・報告する。日付更新をまたいだら、それまでの実行を保存して新しいミッション状態を確認し直す。
