# Web アプリ UI/UX の参照

- Web アプリの画面設計、操作、アクセシビリティを検討するときに参照する。
- まず対象プロジェクトの既存デザインシステム、コンポーネント、トークンを確認する。
- 既存の設計判断と用語を保ち、共通部品がある場合はそれを優先する。
- Material 3 は必要な場合に補助資料として使う。
- 基礎概念は [Material 3 Foundations](https://m3.material.io/foundations/) を参照する。
- 文字組みは [Material 3 Typography](https://m3.material.io/styles/typography/applying-type) を参照する。
- Material 3 の見た目や部品を、既存の製品方針より優先しない。
- アクセシビリティは [WCAG 2.2 Quick Reference](https://www.w3.org/WAI/WCAG22/quickref/) から該当基準を選んで確認する。
- 画面や操作に関係する基準を適用し、対象外の基準まで一律に列挙しない。
- 通常、空、読込、失敗は、その画面や操作で実際に起きる状態だけ扱う。
- 入力が必要な場合は、前提条件と入力方法を明確にする。
- エラー時は問題の箇所と修正・再試行などの次の操作を示す。
- 操作後は、結果が利用者に分かる形で伝わるようにする。
- 状態変化やエラーは、支援技術にも名前と状態が伝わるようにする。
- 色、形、位置だけに情報を頼らず、テキストや支援技術で意味を補う。
- 説明を短くする場合も、入力条件、エラー、操作結果、支援技術への名前と状態を残す。
- 具体的な API の選定や実装手順は、対応する専用スキルに記載する。
