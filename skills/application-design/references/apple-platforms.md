# Apple プラットフォームの UI/UX 参照

- iOS、iPadOS、macOS アプリの画面設計と操作を検討するときに参照する。
- 主な設計資料として [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines) を使う。
- まず対象プロジェクトの既存デザインシステム、コンポーネント、トークンを確認する。
- 既存の設計判断を保ちながら、対象 OS と利用状況に合う HIG の指針を選ぶ。
- Apple の標準コントロールや操作パターンは、画面の目的に合う場合に使う。
- iPhone、iPad、Mac の画面サイズや入力方法に応じて、レイアウトと操作を調整する。
- タッチ、キーボード、ポインタなど、対象アプリで必要な入力方法を確かめる。
- 通常、空、読込、失敗は、その画面や操作で実際に起きる状態だけ扱う。
- 入力が必要な場合は、前提条件と入力方法を明確にする。
- エラー時は問題の箇所と修正・再試行などの次の操作を示す。
- 操作後は、結果が利用者に分かる形で伝わるようにする。
- VoiceOver などの支援技術に、要素の名前と現在の状態が伝わるようにする。
- キーボード操作やフォーカスの移動が、必要な利用者にとって一貫するようにする。
- 色、形、位置だけに情報を頼らず、必要なラベルや説明を用意する。
- 説明を短くする場合も、入力条件、エラー、操作結果、支援技術への名前と状態を残す。
- 数値の寸法や間隔を独自に固定せず、対象プラットフォームの現行指針と既存トークンに従う。
- 具体的な API の選定や実装手順は、対応する専用スキルに記載する。
