# Codex / Claude hooks 同期

Codex と Claude Code の hooks を、登録数ではなくユーザーが求める動作を基準に同期する。

## 正本と証拠

- 各製品の現行設定を正本とし、毎回読み直す。
- `hook-ledger.json` が残っている場合は、過去の意図を知るための読み取り専用資料としてのみ扱う。存在や更新を必須にしない。
- 静的な登録、実装、hook 実行、外部通知の到達を別の証拠として扱う。
- 登録数や parity の一致を完了条件にしない。

## 手順

1. ユーザーがそろえたい動作、同期元、同期先を特定する。依頼から明確なら聞き直さない。
2. 書き込み前に、両製品の現行設定、関連する hook 本体、対象限定のテストを読み取る。
3. 同期元と同期先のイベントを、意味と粒度に基づいて次のいずれかに分類する。
   - `equivalent`: 同じ目的と発火条件を実現できる。
   - `partial`: 目的の一部だけを実現できる、または発火粒度が異なる。
   - `unsupported`: 安全な対応先がない。
4. 変更前に、対象ファイル、対応関係、変更しない範囲、検証方法、未確認事項を含む同期計画を提示する。
5. 明示的な `y/n` 承認を求め、`y` を受け取るまで設定や実装を変更しない。計画依頼だけを変更承認と解釈しない。
6. 承認後は、計画で指定した対象だけを最小変更する。`partial` や `unsupported` を推測で完全同期に変換しない。
7. 保存後に設定を再読し、構文確認、登録の静的確認、対象限定テストを行う。
8. 変更内容、`equivalent`、`partial`、`unsupported`、検証結果、実行時未確認事項を分けて報告する。

## 安全境界

- 別途の明示承認なしに hook を実行しない。
- Keychain、認証情報、トークンを読み取らない。
- 外部通知、ネットワーク、音声、socket を使わない。
- オートメーションを作成、再開、更新しない。
- 対象外の hook、設定、テストを変更しない。
- 実イベントを観測していない場合、実行時の成功や動作同等性を主張しない。
- 古い帳簿や parity テストが廃止済みの継続管理を要求する場合は、競合を報告して停止する。帳簿管理を黙って復活させない。
