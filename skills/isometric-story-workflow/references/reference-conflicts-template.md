# Reference Conflicts

ステップ4で、参照画像・設計・実物資料が一致しない箇所を先に確定する。各項目は空欄、`TBD`、`未定`、`未確認`を残さず、`adopt`には採用する側を明記する。以下は今回の判断を書き換えた例であり、そのまま転記しない。各ストーリーの実際の設計判断・参照・実物データに合わせて書き直す。8Aの「設計上の確定事項」はこのファイルから機械的に転記する。

## 1. 留め継ぎと指組み

- conflict: 参照画像の留め継ぎと設計上の指組みが異なる
- reference_shows: 外観は平滑な留め継ぎとして読める
- design_or_real_data: 署名パーツとして浅い指組みを設計する
- adopt: design: 留め継ぎ
- basis: 画面上で巣箱の構造を読めることを優先し、実装可能な粒度で表現する

## 2. 実物ラングストロス寸法と縦長誇張

- conflict: 実物のラングストロス寸法と画面上の縦長プロポーションが異なる
- reference_shows: 参照画像は縦方向の印象が強い
- design_or_real_data: 実物資料は標準寸法を示す
- adopt: real_data: 実物ラングストロス寸法をそのまま採用
- basis: 物理的な関係を壊さず、固定カメラで主役の読解性を確保する

## 3. 空の巣箱と明るい観察窓

- conflict: 空の巣箱の暗い内部と、参照画像の明るい観察窓が異なる
- reference_shows: 観察窓が明るいアクセントとして見える
- design_or_real_data: 空の内部は暗く、窓越しの明るさは演出である
- adopt: real_data: 暗い内部
- basis: 物語上の観察対象を画面上で認識できることを優先する

## 4. 固定カメラと石4個の可視性

- conflict: 固定カメラのまま四つの石をすべて見せる必要がある
- reference_shows: 参照画像では石の見える個数が構図に依存する
- design_or_real_data: 設計では四つの石がスタンドの署名パーツである
- adopt: design: 固定カメラのまま手前の石のみ可視
- basis: 署名パーツの存在理由を8Cで判定できる構図を優先する

## 5. 側面の入口の有無

- conflict: 参照画像の側面入口の有無と設計上の入口スリットが異なる
- reference_shows: 側面の入口は角度によって見えない
- design_or_real_data: 設計では巣箱の入口スリットを必須とする
- adopt: design: 入口スリット
- basis: クールの機能的署名を固定カメラから読み取れる必要がある
