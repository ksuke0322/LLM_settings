# ステップ8 独立レビュー起動プロンプト雛形

ステップ8A・8B・8Cの独立レビューを起動するときの**プロンプト正本**。3本とも `<...>` を埋めるだけで
起動できる完成形にしてある。ここに書かれた固定文言は変更せず、書き起こし直さない。

判定基準そのものはここに書かない。Acceptance Matrixは `quality-gates.md`、署名パーツと存在理由は
`worksheet-rules.md` と設計書(`design/story_design.md`)を正本とする。本ファイルが持つのは**文面の型**だけである。
返却契約は `step8-review-control.md` の ReviewReport v1 を正本とする。

## 使い方(親向け・雛形の外の手順)

1. `subagent_type: isometric-story-review` で起動する(model:opus・effort:medium はエージェント定義側で固定済み)。
2. 該当する節の雛形をそのままコピーし、`<...>` を実際の値へ置換する。**空欄・「TBD」・「後で決める」が
   残った状態で起動しない**(ワークシート記入ルールと同じ基準)。
3. 起動前に本ファイル末尾の「起動前チェックリスト」を1項目ずつ確認する。
4. 該当しない差し込み節(クール1に「引き継ぎ資産」は無い等)は、節ごと削除する。節見出しだけ残して
   中身を空にしない。
5. 修正ループの2回目以降も**同じ雛形で起動する**。前回の指摘内容・こちらの反論・修正履歴は渡さない
   (独立性が壊れる)。渡してよいのは新しいレンダー画像と、更新された実測値だけである。candidate `.blend`と
   render setが不変なら起動せず、ReviewLedgerを検証して親へ戻す。

## 共通の禁止事項(8A・8B・8Cすべてに効く)

1. **8Bに8C観点を混ぜない。** 8Bは「物として自然か」だけ。署名パーツが設計どおり実現されているか・
   存在理由が読めるかは8Cで判定する。役割の混載は「PASSなのに低品質」の事故を実際に生んでいる。
2. **8B・8Cに生成参考画像を渡さない。** 参考画像は別の生成AIによる簡易生成物で非現実的な形状を含むため、
   常識判断がそれに引きずられる。渡すのは実物資料だけ。
3. **作業経緯・既知の課題・過去の指摘履歴・こちらの言い訳を渡さない。** 製作者バイアスの持ち込みを防ぐ。
4. **`general-purpose` 等の汎用エージェントで起動しない。** 製作スレッドのモデルを継承してしまい、
   判定の一貫性が崩れる。必ず `subagent_type: isometric-story-review` を指名する。
5. **ReviewReport v1に定義されていないキーを追加しない。** `history`、前回レビュー、修正履歴、反論、
   実装手順などを別名のキーで返さず、固定されたJSONフィールドだけを返す。

## 起動前チェックリスト

雛形を埋め終えたら、起動前に1項目ずつ確認する。1つでも×があれば起動しない。

- [ ] `subagent_type: isometric-story-review` を指定した(汎用エージェントではない)
- [ ] `<...>` のプレースホルダが1つも残っていない。「TBD」「後で決める」も残っていない
- [ ] 画像パスが**すべて絶対パス**で、実在する(相対パスはリンク切れ事故の実績あり)
- [ ] 8B・8Cで**生成参考画像を渡していない**(実物資料のみ)
- [ ] 8Bに8C観点(署名パーツの実現・存在理由)を混ぜていない
- [ ] 作業経緯・既知の課題・前回の指摘・修正履歴を書いていない
- [ ] クール2以降なら「判定範囲」で新規追加分と引き継ぎ資産を切り分けた
- [ ] 「実測済みの数値」節に、目視カウントで誤判定されやすい項目(本数・クリアランス・断面)を入れた
- [ ] 「承認済みの設計判断」に、waiver として扱うべき既知の実物差をすべて挙げた(挙げ漏れは
      「毎回同じ指摘が再発する」原因になる)
- [ ] 8Bの「特に見てほしい観点」が案件固有の内容で埋まっている(定型文のままにしない)
- [ ] 出力形式の末尾に**明示的な0件結論**を求める一文がある
- [ ] `step8_parent_baseline`を親が確認・保存し、基準画像、現行レンダー、視覚アンカー、許容差を独立レビュアーへ渡していない
- [ ] candidate `.blend`とrender setのSHA-256、Acceptance Matrix revision、attempt番号をReviewLedgerへ記録した
- [ ] ReviewReport v1をJSONだけで返し、`status`、絶対パス、evidence画像、指摘fingerprintをvalidatorで確認する
