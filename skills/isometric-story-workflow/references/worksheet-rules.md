# ワークシート: 記入ルール

ステップ2・3で実際に埋める4つの表(オブジェクト一覧表/寸法比例表/Collection構成表/World・ライティング表)と配色・画面方針メモについて、以下の定義に従う。空欄や「TBD」が残った状態でステップ4に進んではいけない。

### オブジェクト一覧表

列: 名前 / 分類 / 初出クール / 前クール完成物との関係 / 動き方分類 / 登場演出タイプ / 強化技法(a〜d) / サイズ比較対象 / 意図する見た目(1文) / アンビエントループ候補(有無)

- 分類は「主体(1つ)」「周辺要素(2〜3種)」「スケール対比物(1つ以上)」のいずれかに必ず割り当てる。完成時の総オブジェクト数は人が一見で数えられる程度(目安5〜10個)に抽象化する。
- 動き方分類は4分類(縦構造・上から設置・発光・水平移動)のいずれかに必ず割り当てる。割り当てられない場合は要素の定義自体を見直す。
- **登場演出タイプ**: 「動き方分類」が同じでも実際の演出は複数のバリエーションがあり得る。以下のカタログから各要素に1つ選んで記入する(カタログにない演出を考案してもよいが、その場合も1文で明記する)。**同一クール内で、主体・周辺要素に分類される要素同士が同じ登場演出タイプを使うことを禁止する**(スケール対比物・背景ディテールは対象外。要素数が少なくカタログ内で選択肢が尽きる場合は、カタログにない独自演出を1つ以上作ってでも重複を避ける)。
  - 直下落下(ストレート): 上空から真下に落ちて着地、着地後は動かない
  - 落下+バウンド: 落下後、着地位置で軽くオーバーシュートしてから収束する
  - 空中出現→収束移動: 目標位置の近くでscale 0→1で出現した後、短い距離を移動しながら最終位置・角度に収まる
  - 下から成長: 設置面に底面を固定したままscale.zで伸び上がる(既存の縦構造パターン)
  - 回転しながら収束: 出現時に余分な回転(目安90〜180度)を伴い、最終姿勢まで回転しながら収まる
  - フェード+わずかなドリフト: 透明度0→1のフェードインと共に、ごく小さい移動(全体サイズの5〜10%程度)を伴う
  - 水平移動+イージング強調: 既存の水平移動パターンにオーバーシュート等の強調イージングを付与したもの(強化技法(c)と組み合わせる場合はここに記入)
- **強化技法(a〜d)**: 各クールにつき最低1要素は、以下のいずれかを記入する(「—」のみで全要素が埋まっている状態は不可)。
  - (a) 同一区間で複数のサブパーツ/エフェクトを同時に動かす
  - (b) 強化対象の遷移時間を他要素より長く取る(目安: 通常1.0〜1.5秒に対し2.0〜2.5秒)
  - (c) イージングを強調する(オーバーシュート等)
  - (d) 強化対象にのみ追加のディテール(複数の発光体、パーティクル的な小要素等)を付与する
- **サイズ比較対象**: 各要素について比較先を1つ以上記入する。比較先が存在しない要素のみ「—」と明記する。チェックリストでは、列挙された全ペアで最低30〜50%以上のサイズ差があることを確認する。
- **意図する見た目(1文)**: 各要素(特に装飾品・小物・取り付け付属品)について、「何が・どこに・どの向きで見えるべきか」を実装前に1文で記入する(例: 「オールは船体中央付近、左右の舷側から斜めに突き出し交差気味に見える」)。実装後、`blender-isometric-rules`の`references/review-checklist.md`「構造別クローズアップ検証」でこの列の記載と実装を比較する。
- **アンビエントループ候補(有無)**: 完成state到達後も常時ゆらぎ続けて違和感がない要素(水面・発光パーツの明滅・空/煙等)には「有: ○○がゆっくり流れる/明滅する」等、具体的なループ内容を一言記入する。該当しない要素は「無」と明記する(空欄不可)。ここで指定した要素は`blender-isometric-rules`6章「主stateアニメーション完了後はAmbient Loop Animationで静止区間を作らない」の実装対象になる。
- 「前クール完成物との関係」は必ず一言(付属する/隣接する/役割を果たす等)で記入する。
- 1クールにつき新規追加する「要素種類」は基本1つ(本体パーツと周辺要素パーツは同時に追加してよい)。
- 決め方のコツ: 最初に「最終クール完成時の見た目」を1文で決め、それをパーツに分解して各クール・stateへ逆順で振り分ける(完成状態からの逆算)。

### 背景ディテール(オブジェクト一覧表には個別行を作らない)

- 「背景ディテール1個」とは「個別の独立したメッシュオブジェクト」または「Scatter/パーティクルにより生成された視認可能な独立した塊」を1個と数える(クローン全体を1個として数えない)。
- **配置方法はGeometry Nodesを既定手法とする**(`blender-isometric-rules`2章参照)。手動配置は例外的な選択肢。
- 種類は最低5種類以上、各種類の代表寸法(直径)は近接主要構造物の基準変数の25%〜55%の範囲に収める。
- 各背景ディテールの種類ごとに配置平面(岩場上面/水面等)を設計段階で明記する(実装時に成り行きで決めない)。
- 「生成しただけ」では不可: カメラから各背景ディテールへray_castし、主要構造物に遮蔽されていないことをコードで確認する(`blender-isometric-rules`の`scripts/gn_scatter.py`の`count_visible_from_camera`を使う)。カメラから視認可能な個数が15〜30個の目安を満たすことを必須とする。
- 接地ルール: 各背景ディテールのZ位置は、配置座標が地形/水面どちらの表面上にあるかを判定し、実際の表面高さに合わせて配置する(`blender-isometric-rules`の`scripts/raycast_snap.py`を使う)。

### 寸法比例表

- 基準値(主体の中心寸法)を1行目に固定し、残りの行はすべて比率で埋める。絶対値の手打ちは禁止。
- 背景要素(地面・岸壁等)の寸法も、主要構造物の寸法を基準に比例で決める(テーマ全体基準だけで決めるとスケールバランスが崩れやすい)。
- **`STAGE_EXTENT`**: 「舞台全体(地面・水面・背景ディテールを含む可視範囲)の半径または半幅」。主要構造物より外側の背景要素もこの範囲内に収める。目安は主要構造物の高さ/幅の2.5〜4倍程度。複数クール構成の場合、クール2以降で追加される要素(桟橋等)もこの範囲内に収まることを確認する。
- 複数クール構成の場合、クール2以降で追加される部分の寸法を独立した新しい定数として決めてはならない。必ずクール1主体の寸法定数からの比例で定義する。
- **新規構造物と引き継いだ背景ディテールの衝突を避ける(必須)**: クール2以降で新規の主要構造物(桟橋等)を追加する場合、引き継いだ背景ディテールスキャッターのSelectionマスクに除外ゾーン(新規構造物の占有領域+マージン)を追加する。座標範囲を設計段階で明記する。

### Collection構成表

- 地面/水面など「stateに関係なく常に表示されるもの」は`common_environment`相当の専用Collectionを必ず1行用意し、全stateで常時表示する(state専用Collectionに入れてstate0に紐付けてはならない)。

### 質感タイプ・構造タイプ・アセット方針表(PolyHaven選定)

- **PolyHaven対象はこの段階(ステップ2・3、Blender起動前)で実際に検索し確定する**。Blenderが起動していないと使えない`blender-mcp`の`search_polyhaven_assets`は使わず、PolyHavenの公開API(`https://api.polyhaven.com/assets?type=textures&categories=<カテゴリ>`)を`ctx_fetch_and_index`+`ctx_search`(または同等のfetchツール)で直接取得する。返ってくる名前・タグ・説明文から、テーマの質感・色味に合うアセットIDを実在確認した上で選び、表の「アセット方針」列に具体的なアセットID(例: `coast_sand_rocks_02`)を記入する。存在しないアセット名を推測で書いてはならない。
- 該当するアセットが見つからない場合は「プロシージャルで代替」と明記する(空欄・「検索予定」等の未確定状態は不可)。
- **ここで確定したPolyHaven対象は、ステップ6で実際にダウンロード・適用してみた結果(質感・色味がシーンに合うか)で覆る可能性がある**。これはAPIのメタデータだけでは判断できないため正常な流れだが、もし合わない場合でも実装者(AI)が自己判断でプロシージャルに差し替えてはならない。ステップ6の該当箇所を参照しユーザーに確認を取ってから決定する。
