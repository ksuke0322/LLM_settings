# Task Progress Dashboard

複数の作業が一日の中で連なっている場合、または一つの作業に複数の工程があり、途中で中断・再開される可能性がある場合に、ローカルの進捗管理HTMLを作成・更新する。

## 適用条件

次のいずれかに当たるときは、ユーザーから毎回「進捗表を作って」と言われなくても適用を検討する。

- 連続して実施するタスクが目安として3つ以上ある。
- 一つのタスクが複数の段階に分かれ、長時間の調査・実装・検証・報告をまたぐ。
- 中断後に別のセッションや担当者が再開する可能性がある。
- ユーザーが進捗表、タスク一覧、HTMLの進捗ページを明示的に求めた。

単発の質問、短い修正、数分で終わる確認には作成しない。適用するか迷う場合は、作業の長さと再開可能性を優先して判断する。

## 成果物

自己完結したローカルHTMLを一つ作成または更新する。外部CSS、外部JavaScript、外部画像、外部APIには依存しない。

保存先は次の優先順位で決める。

1. ユーザーが指定した既存の進捗ページを更新する。
2. 既存のプロジェクトやworktreeに進捗成果物の慣例があれば、それに従う。
3. 慣例がなければ、現在のタスクに紐づくworktreeまたは成果物ディレクトリに `progress-YYYY-MM-DD.html` を作成する。

既存ページを更新するときは、ユーザーが書いた注記や構成を読み取り、状態変更に必要な範囲だけを変更する。正本、state、manifest、注文、保有、Git履歴、remote、外部サービスは、このskillのためだけに変更しない。

## ページ構成

一覧の読みやすさとタスク順序を優先し、最小限の構成にする。

1. ヘッダー
   - 日付または対象期間
   - 最終更新時刻
   - 全体の完了数と対象数
   - 現在作業中のタスクまたはセクション
2. 判断・保留・阻害の要約
   - ユーザーの判断が必要な項目
   - 意図的に後回しにした項目
   - 前提不足、失敗、外部待ちなどで進められない項目
   - 各項目はID、理由、次に必要な判断または解消条件を短く示す
   - 該当項目がない場合は空の大きな欄を作らず、省略する
3. タスク一覧
   - ユーザーまたは計画で定めた順序を保つ
   - 大きな作業単位ごとにセクションを分ける
   - 各行は原則として `ID / 状態 / タスク名` の簡潔な形にする
   - タスクの順番そのものを、作業の進み方を表す情報として扱う
4. 最後のお願い・再起動・手動操作など
   - 通常のタスク件数に混ぜず、別セクションにする

`次の一手` 専用列や、詳細な証跡列を標準構成に追加しない。必要な情報がある場合は、タスク名または判断・保留・阻害の要約に短く含める。

## 状態の扱い

プロジェクト固有の表記があれば維持する。新しく作る場合は、次の意味が伝わる表記を使う。

- `済` / `完了`: そのタスクで定めた完了条件を満たした。
- `作業中`: 現在の作業対象である。
- `未着手`: まだ開始していない。
- `後回し`: 意図的に今回の作業対象から外した。
- `ユーザー待ち`: ユーザーの判断、入力、承認が必要で止めている。
- `阻害`: 前提不足、失敗、環境問題などにより、現時点では進められない。

`後回し`、`ユーザー待ち`、`阻害` は、単なる `未着手` と区別して上部の要約にも反映する。状態を推測できない場合は、勝手に完了や作業中へ変換せず、`未確認` または `要確認` として残す。

## 集計規則

完了数と全体数は、HTML内のタスク行から一貫して計算する。

- 通常のタスク行だけを集計対象にする。
- 「最後のお願い」や説明文は、タスクとして明示されていない限り分母に含めない。
- `後回し`、`ユーザー待ち`、`阻害` を分母から外す場合は、そのルールをページ上に示す。原則は分母に含める。
- ヘッダーの集計値と、表の状態行から数えた値が一致することを確認する。
- 一致しない場合は数値を推測で合わせず、集計ルールまたは状態行を見直す。

## 更新のタイミング

次のような意味のある状態変化が起きたときにページを更新する。

- タスクを開始した、完了した、後回しにした。
- ユーザー待ちや阻害が発生した、解消した。
- 現在作業中のセクションが変わった。
- 作業を中断して再開可能な状態になった。

細かなコマンド実行ごとに再生成せず、ページを開いた人が判断できる変化に絞る。更新時刻は実際の更新時刻を記載し、未確認の時刻を補完しない。

## HTML品質

- `<title>`、見出し、表の見出しを設定する。
- 状態を色だけで表さず、文字や記号でも判別できるようにする。
- 表には適切な `<caption>` と `<th scope="col">` を付ける。
- 小さい画面でも読めるように、長いタスク名を無理に一行へ固定しない。
- 日本語のHTMLエスケープを行い、タスク名に含まれる記号でレイアウトやタグを壊さない。
- 外部リソースを参照せず、ファイル単体を開いて内容を確認できるようにする。

## 完了時の確認

ページを作成または更新したら、少なくとも次を確認する。

- 指定または選択した保存先にファイルが存在する。
- 日付、最終更新、現在位置、タスク件数が実際の内容と一致する。
- 判断・保留・阻害の要約に、該当するIDが漏れていない。
- タスクの順序とセクション構成が、元の計画から意図せず変わっていない。
- HTMLが外部リソースなしで開ける。

入力不足、生成失敗、保存先不明などがある場合は、ページを完成扱いにせず、`未確認`、`部分生成`、または `PROGRESS_PAGE_UNAVAILABLE` として報告する。タスク自体の進捗や業務成功を、ページファイルの生成成功だけから推測しない。
